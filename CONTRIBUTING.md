# Development conventions

## Layout

| Path | Contents |
| --- | --- |
| `rtl/` | The single parameterized design, `edgemac_top.sv`, for `LANES` = 1 or 4 |
| `docs/specification.md` | Arithmetic, stream, reset, error, and register contract |
| `verification/reference/` | Scalar Python oracle, written from the specification and independent of the RTL |
| `tests/` | Unit tests for the oracle |
| `verification/cocotb/` | Cycle-level testbench, scoreboard, and cycle benchmark |
| `verification/formal/` | SymbiYosys protocol and arithmetic harnesses |
| `verification/smoke/` | Toolchain smoke test (signed multiplier) |
| `synthesis/` | Yosys generic-mapping script template |
| `scripts/` | Reproducible check, mutation, and evidence-export commands |
| `results/` | Machine-readable evidence regenerated by `scripts/export_evidence.py` |

## Changing behavior

Update `docs/specification.md` before changing externally visible behavior, and keep both lane counts on the same RTL. Every persistent register has one clocked writer. Reset has priority over every other event on the same edge.

Keep the oracle independent of the RTL. The scoreboard computes each expected value from the oracle and decodes operands from observed handshakes, never from DUT internals.

## Checks to run

Run the affected check before integrating a change, then the full regression:

| Change | Command |
| --- | --- |
| Arithmetic contract or oracle | `python scripts/check.py oracle` |
| RTL | `python scripts/check.py lint` and `python scripts/check.py sim` |
| Protocol or arithmetic properties | `python scripts/check.py formal` |
| Datapath structure | `python scripts/check.py synth`, `perf`, and `timing` |
| Anything | `python scripts/check.py all`, then `python scripts/check_mutations.py` |

Per-configuration checks accept `--lanes 1` or `--lanes 4`; both run by default.

When a check fails, keep the seed, lane count, failing cycle, and exact command. Formal counterexample traces are written under `build/formal/`. Distinguish bounded checks (BMC to a depth) from unbounded proofs (PDR) when reporting formal results.

Report outcomes with one of: VERIFIED (a check executed and passed), MEASURED (a tool-reported count), ESTIMATED (a model-based figure such as FPGA clock), FAILED, BLOCKED, or NOT TESTED. Make no physical-silicon or board-level claims; none were measured.
